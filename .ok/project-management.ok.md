# Project Management OK

This repository uses DotOK for project management.

## Ideal End State

- TRUE: `.ok/*.ok.md` files are the evergreen constitutional source of truth for what must be true.
- TRUE: `.tasks/` is the only active execution system; task files are ephemeral, archived, and regenerated by reconciliation loops.
- TRUE: `.specs/**` may remain as durable design, research, and requirement references, but each active spec area is explicitly pointed to by one or more `.ok/*.ok.md` files.
- TRUE: Human blockers are consolidated in `.tasks/blocked-by-user/needs-attention-YYYY-MM-DD.md` rather than scattered across task files, chats, or notes.
- TRUE: Status summaries such as `README.md` and `STATUS.md` are derived communication artifacts, not the canonical task system.

## States We Do Not Want

- FALSE: Any file named `TODO.md` exists anywhere in the repository.
- FALSE: Long-lived backlog systems such as `tracker/`, Jira-style ticket lists, or checklist specs are treated as the active source of execution truth.
- FALSE: A `.specs/**` document is relied on as enduring truth without a corresponding `.ok/*.ok.md` file that names and governs that area.
- FALSE: Task files live indefinitely instead of being archived and replaced by a fresh hierarchy from the latest gap analysis.
- FALSE: Multiple documents disagree about current status and the disagreement is allowed to persist without reconciliation.

## Required Governance Rules

- TRUE: Every reconciliation loop evaluates repository reality against `.ok/*.ok.md` files first.
- TRUE: New work starts by updating or adding the relevant `.ok/*.ok.md` file before generating fresh `.tasks/*.md` work orders.
- TRUE: If an older process artifact is still present during transition, its existence is treated as a gap to reconcile, not as permission to keep using it as authority.
- TRUE: Each active spec area under `.specs/` gains a corresponding `.ok` file that points back to the relevant spec documents.
