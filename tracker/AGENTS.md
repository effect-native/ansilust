# Tracker Directory - Archived Guidance

`tracker/` is retained only as historical context from the pre-DotOK workflow.

## Status

- Project-management authority lives in `.ok/project-management.ok.md`.
- Active execution state lives in `.tasks/`.
- Do not create, update, complete, prioritize, or query live work from `tracker/`.

## What This Directory Represents

- Historical task records and examples from the legacy tracker flow.
- A non-authoritative snapshot of how work used to be organized.
- Archival context that may help interpret older references, IDs, or documents.

## What This Directory Does Not Represent

- The current task queue.
- Current status, priorities, blockers, or ownership.
- The procedure for starting or finishing work.

## Reading Legacy Tracker Content

- Treat task files and index summaries as dated snapshots.
- Expect statuses, counts, and priorities here to be stale.
- If historical tracker items need modern handling, translate them into DotOK artifacts under `.ok/` and `.tasks/` instead of reviving the legacy workflow in place.

## Historical Notes

- Legacy tracker IDs such as `GAP-PARS-001` or `BUG-IR-002` may still appear in older commits, notes, or specs.
- Schema details in archived task files are preserved for reference only.
- `tracker/index.md` is an archive snapshot, not a live runbook.
